### Schema
- `supabase/migrations/03_phase4_users_and_tier.sql`:
  - `public.users` table mirrors `auth.users` with `tier` column
    (`free` | `pro`, default `free`).
  - Trigger `on_auth_user_created` auto-creates `public.users` row on every
    `auth.users` insert (security definer, avoids RLS). Backfills existing
    rows.
  - RLS: self-read only on `public.users`. Tier writes go through the
    service-role key (Phase 5 Stripe webhook will own this).
  - Adds FK `plans_owner_user_id_fkey` on `plans.owner_user_id` →
    `auth.users(id)`, ON DELETE CASCADE. Wrapped in DO block to stay
    idempotent.
- `supabase/schema.sql` mirrors the same definitions so a fresh install is
  consistent.

## What blocked us

- Supabase shared SMTP rate-limited the magic-link email on the user's
  primary address (~3-4/hour per recipient). Sign-in smoke test
  postponed to tomorrow.
- Resend recommended as the production fix:
  - 3,000 emails/month, 100/day on free tier.
  - Custom SMTP config in Supabase Authentication → SMTP Settings, host
    `smtp.resend.com`, port 465, username `resend`, password = Resend API
    key, sender `noreply@aisolutionmaven.com` (after DNS verification).
