### Sign-in policy: `shouldCreateUser: false`

User reported confusion: clicking "Sign in" with a new email was
silently creating an account, then redirecting to PlanSight with the
"Activate PlanSight" banner showing — confusing because the user
thought they had just signed in, not signed up. Root cause:
Supabase's `signInWithOtp` defaults to `shouldCreateUser: true`.

Fix in `components/auth/SignInForm.tsx`:
- Sign-in path (no product param): `shouldCreateUser: false`. Magic
  link only sent for existing accounts.
- Sign-up path (`product=plansight-ai`): `shouldCreateUser: true`.
- Unknown email on Sign in path: amber "No account for that email"
  panel with "Sign up for PlanSight" button + "Try a different email"
  reset. Loose error matcher ("not found" / "signups not allowed" /
  "does not exist") so Supabase wording changes don't bypass the
  friendly handling.
- Form chrome rebranded simultaneously: `rounded-md` over
  `rounded-2xl`, cyan-700 button over gradient, cyan-400 focus ring.

The /signin page itself reframes by context: "Sign up for PlanSight"
when product param is present, "Welcome back" + "New to PlanSight?
Sign up here →" link otherwise.
